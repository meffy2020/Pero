# Dev Notes

데이터 적재, 동기화, 시연 안정화처럼 "왜 바뀌었는지"를 남겨야 하는 작업은 이 폴더에 기록한다.

## 파일명 규칙

- `YYYY-MM-DD-주제.md`
- 예시: `2026-04-21-koreatour-sync-workflow.md`

## 언제 기록할지

- ETL 파이프라인을 추가하거나 수정했을 때
- 자동화 워크플로/배포/시연 운영 규칙이 바뀌었을 때
- 데이터 품질 이슈나 외부 API 장애 대응이 필요했을 때

## 기본 섹션

1. `배경`
2. `이번 변경`
3. `실행/검증`
4. `영향 파일`
5. `후속 작업`
6. `커밋/PR`

짧게 쓰되, 다음 사람이 같은 작업을 바로 재현할 수 있을 정도의 정보는 남긴다.
