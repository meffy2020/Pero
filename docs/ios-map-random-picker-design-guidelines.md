# Pero iOS 지도 우선 랜덤 추천 디자인 지침

작성일: 2026-06-04

## 1. 핵심 방향

`Pero` iOS의 메인 화면은 항상 풀스크린 지도다.

사용자는 앱에 들어오자마자 현재 보고 있는 지도 영역을 보고, 하단 가운데의 랜덤 버튼 하나로 장소를 뽑는다. 장소 추천, 식당 추천, 랜덤 코스 추천은 별도 홈 카드가 아니라 같은 지도 위에서 바뀌는 모드다.

중요한 원칙:

- 지도는 배경이 아니라 메인 화면 자체다.
- 지도 위 UI는 최대한 적게 둔다.
- 검색은 보조 기능이다. 검색바가 첫 화면의 주인공이 되면 안 된다.
- 랜덤 뽑기 버튼은 하단 가운데의 유일한 강한 CTA다.
- 결과는 새 화면으로 밀어내지 말고, 같은 지도 위에서 선택 핀과 하단 시트로 보여준다.

## 2. 레퍼런스 해석

제공한 레퍼런스의 좋은 점:

- 지도 면적이 화면 대부분을 차지한다.
- 검색, 카테고리, 현재 위치, 레이어 같은 요소가 지도 위에 떠 있다.
- 흰색 표면과 검은색 아이콘이 선명하고 이해하기 쉽다.
- 하단 시트가 올라와도 지도 맥락이 유지된다.

Pero에서 그대로 가져오면 안 되는 점:

- 검색바가 너무 크면 `랜덤 추천 앱`이 아니라 `지도 검색 앱`처럼 보인다.
- 카테고리 칩이 많아지면 지도보다 필터가 먼저 보인다.
- 하단 탭이 많아지면 메인 액션인 랜덤 뽑기가 약해진다.
- 광고, 피드, 프로필 카드 같은 생활앱 요소는 Pero 메인에 맞지 않는다.

따라서 Pero는 레퍼런스의 `지도 우선 구조`, `흰색 플로팅 UI`, `검은색 아이콘`, `작은 칩`, `하단 시트`만 가져오고, 요소 수는 더 줄인다.

## 3. 첫 화면 구조

필수 레이어:

1. 풀스크린 지도
2. 상단의 작은 현재 영역 표시 또는 축약 검색 진입점
3. 장소 / 식당 / 코스 모드 칩
4. 현재 위치 버튼
5. 하단 가운데 랜덤 뽑기 버튼
6. 결과가 있을 때만 올라오는 하단 시트

권장 배치:

```text
┌─────────────────────────┐
│ status bar               │
│ [노원구 상계동 ▾]        │
│ [장소] [식당] [코스]      │
│                         │
│          지도            │
│     작은 후보 핀들        │
│                         │
│                 [◎]     │
│                         │
│        [ 랜덤 뽑기 ]      │
└─────────────────────────┘
```

검색이 필요할 때만:

```text
┌─────────────────────────┐
│ [⌕ 이 지역에서 검색]     │
│ [장소] [식당] [코스]      │
│          지도            │
│        [ 랜덤 뽑기 ]      │
└─────────────────────────┘
```

상단 검색바는 Naver Map처럼 크게 둘 수 있지만, 기본 상태에서는 `검색창`보다 `현재 영역 표시`가 더 적합하다. Pero의 핵심은 사용자가 검색어를 입력하는 것이 아니라 현재 지도 안에서 무작위 선택을 받는 것이다.

## 4. UI 요소 수 제한

메인 지도 위에 동시에 보이는 요소는 아래 수준을 넘기지 않는다.

- 상단 영역: 1줄 또는 최대 2줄
- 모드 칩: 3개 고정 (`장소`, `식당`, `코스`)
- 우측 플로팅 버튼: 최대 2개 (`현재 위치`, `지도 설정/레이어`)
- 하단 강한 CTA: 1개 (`랜덤 뽑기`)
- 하단 탭바: MVP에서는 숨기거나 최소화한다

하지 말 것:

- 음식점, 카페, 편의점, 친구위치 등 많은 카테고리 칩을 동시에 늘어놓지 않는다.
- 지도 위에 카드, 광고, 피드, 프로필 요약을 상시 노출하지 않는다.
- 하단에 여러 개의 큰 액션 버튼을 만들지 않는다.
- 랜덤 뽑기와 검색을 같은 시각적 강도로 두지 않는다.

## 5. 랜덤 뽑기 CTA

랜덤 버튼은 Pero 메인 화면의 중심이다.

권장 형태:

- 위치: 하단 가운데, 홈 인디케이터와 안전 영역 위
- 형태: 큰 pill 버튼 또는 둥근 캡슐형 버튼
- 높이: 56-64pt
- 좌우 패딩: 22-28pt
- 텍스트: `랜덤 뽑기`, `이 지역에서 뽑기`, `뭐 하지?`
- 아이콘: 주사위, 반짝임, 위치 핀 중 하나

상태:

- 기본: 오프화이트 표면 + 예쁜 검정 텍스트 + 포인트 컬러 작은 아이콘
- 누르는 중: 포인트 컬러 `#9bb7d4` 링 또는 지도 스캔 효과
- 결과 선택 후: 버튼 텍스트를 `다시 뽑기`로 변경

버튼 주변에는 보조 문구를 길게 두지 않는다. 필요하면 버튼 위 작은 캡션 한 줄만 허용한다.

예시:

```text
현재 화면 후보 18개
[ ✦ 랜덤 뽑기 ]
```

## 6. 랜덤 시각 효과

효과는 재미있어야 하지만 지도 선택 UX를 방해하면 안 된다.

권장 순서:

1. 버튼 탭
2. 현재 지도 영역 안 후보 핀들이 0.4-0.7초 정도 가볍게 pulse
3. 지도 중앙에서 포인트 컬러 링이 퍼짐
4. 선택된 핀이 살짝 확대되고 나머지 핀은 약하게 흐려짐
5. 하단 결과 시트가 올라옴

금지:

- 슬롯머신, 룰렛, 큰 모달, 전체 화면 뽑기 애니메이션
- 지도 화면을 가리는 보상형 연출
- 1초 이상 사용자를 기다리게 하는 과한 연출

## 7. 결과 하단 시트

결과는 지도 위에 바로 보여준다.

기본 높이:

- 접힌 상태: 120-180pt
- 확장 상태: 화면의 45-60%

접힌 시트 정보:

- 장소명
- 카테고리
- 거리
- 추천 이유 한 줄
- `길찾기`, `상세`, `다시 뽑기` 중 핵심 액션

식당 결과:

```text
미미스낵
식당 · 420m
지금 지도 안에서 가볍게 먹기 좋은 곳
[길찾기] [상세] [다시 뽑기]
```

코스 결과:

```text
오늘의 짧은 코스
카페 → 산책 → 식당 · 약 42분
현재 지도 안 후보로 구성
[코스 보기] [다시 뽑기]
```

## 8. 컬러 시스템

사용자 지정 컬러 방향:

- 메인 컬러: 오프화이트
- 텍스트/아이콘: 예쁜 검정
- 포인트 컬러: `#9bb7d4`

권장 토큰:

| 역할 | 색상 | 용도 |
| --- | --- | --- |
| `paper` | `#f7f6f2` | 오프화이트 앱 표면 |
| `surface` | `#fffefa` | 플로팅 검색/칩/시트 표면 |
| `surfaceMuted` | `#eeeee9` | 비활성 칩, 얇은 구분면 |
| `ink` | `#171a1d` | 기본 텍스트, 아이콘 |
| `inkSoft` | `#34393e` | 보조 텍스트 |
| `muted` | `#8b9198` | placeholder, 보조 라벨 |
| `line` | `#dedfdc` | 경계선 |
| `accent` | `#9bb7d4` | 선택, pulse, 작은 포인트 |
| `accentDeep` | `#6f92b4` | 눌림/강조 상태 |
| `accentPale` | `#dce8f2` | 선택 배경, 칩 active 배경 |

오프화이트는 너무 노랗게 가면 지도와 어울리지 않는다. `#f7f6f2` 정도의 따뜻함만 사용한다.

검정은 순수 `#000000`보다 살짝 낮춘 `#171a1d`를 기본으로 사용한다. 포인트 컬러 `#9bb7d4`와 같이 쓸 때 더 부드럽다.

## 9. 지도 색감

지도는 기본 지도 그대로 두되 UI가 얹혔을 때 차분해 보여야 한다.

원칙:

- 지도 자체 채도는 낮춘다.
- 도로/건물 라벨은 읽히되 너무 강하지 않아야 한다.
- 후보 핀은 포인트 컬러 또는 검정/화이트 조합으로 작게 표시한다.
- 선택 핀만 확실하게 커진다.

마커 규칙:

- 기본 후보 핀: 작은 원형 dot 또는 작은 pin
- 선택 핀: `accent` 외곽 링 + 흰색 중심
- 현재 위치: 시스템 블루를 그대로 쓰기보다 `accentDeep`에 맞춰 조정
- 코스 모드: 1, 2, 3 번호가 붙은 작은 waypoint

## 10. 타이포그래피

iOS 시스템 폰트를 사용한다.

권장:

- 큰 제목은 메인 지도 위에 상시 노출하지 않는다.
- 버튼과 칩은 15-17pt, semibold 중심
- 하단 시트 장소명은 20-24pt, bold
- 설명은 13-15pt, regular
- 자간은 0

메인 화면에서는 문장보다 위치와 액션이 먼저 보여야 한다.

## 11. 컴포넌트 규칙

### 칩

- radius: pill
- 높이: 38-44pt
- active: `accentPale` 배경 + `ink`
- inactive: `surface` 배경 + `inkSoft`
- 아이콘은 한 개만 사용

### 플로팅 버튼

- 크기: 44-48pt
- 배경: `surface`
- 아이콘: `ink`
- 그림자는 아주 약하게만 사용

### 하단 시트

- 배경: `surface`
- 상단 핸들: `line`
- radius: 24-30pt
- 내부 여백: 20-24pt
- 지도와 분리되지만 무거운 카드처럼 보이면 안 된다.

### 검색 진입점

- 기본 상태에서는 전체 검색바보다 작은 위치 pill을 우선한다.
- 검색 모드에 들어갔을 때만 큰 검색바를 연다.
- placeholder는 `장소·식당·코스 검색` 정도로 짧게 유지한다.

## 12. 화면별 지침

### 메인 지도

- 앱 진입 첫 화면.
- 지도는 safe area 뒤까지 꽉 찬다.
- 모든 UI는 지도 위에 floating으로 배치한다.
- 랜덤 버튼이 가장 강한 요소다.

### 결과 선택 상태

- 선택 핀은 지도 위에 유지한다.
- 하단 시트가 올라와도 지도는 최소 40% 이상 보여야 한다.
- `다시 뽑기`는 하단 시트 안 또는 기존 CTA 자리에 유지한다.

### 내 정보 / 설정

제공한 레퍼런스처럼 오프화이트 배경과 흰색 카드 구조를 사용할 수 있다.

단, Pero의 메인 경험과 분리한다.

- 카드형 UI는 `내 정보`, `저장한 장소`, `최근 뽑은 결과` 같은 보조 화면에서만 사용한다.
- 메인 지도 화면에는 카드형 서비스 메뉴를 가져오지 않는다.
