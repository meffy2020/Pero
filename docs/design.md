# Pero 디자인 문서

> iOS 앱의 최신 메인 방향은 `풀스크린 지도 + 현재 지도 영역 기반 랜덤 뽑기`다.
> iOS 화면을 수정할 때는 이 문서보다
> [ios-map-random-picker-design-guidelines.md](./ios-map-random-picker-design-guidelines.md)를 우선한다.

## 1. 제품 정의

- `Pero`는 관광지 중심 추천 테마맵 서비스다.
- 기본 경험은 `테마 선택 -> 지도 탐색 -> 장소 상세 해석`이다.
- 검색은 메인 경험이 아니라 보조 탐색 기능이다.
- 대시보드형 제품으로 보이면 안 된다.

## 2. 데이터 전략

- 서울권은 `스마트서울맵`을 우선 활용한다.
  - 주소 체계
  - 배경지도 맥락
  - 도시생활 테마 해석
- 전국 기본 관광 데이터는 `한국관광공사 TourAPI`로 고정한다.
- 외부 API는 프런트에서 직접 호출하지 않는다.
- 프런트는 백엔드 ETL/캐시 뒤의 응답만 사용한다.

## 3. 화면 구조

프런트의 기본 구조는 아래 4개 블록으로 정리한다.

1. Hero
- 서비스 정의와 데이터 전략을 짧게 설명한다.
- 서울 특화 / 전국 fallback 구조를 한눈에 보여준다.

2. Theme Selection
- 사용자가 먼저 테마를 고르게 한다.
- 테마는 문장형 검색보다 앞에 배치한다.
- 각 테마는 관광 맥락이 분명해야 한다.

3. Map Explorer
- 지도는 메인 탐색 영역이다.
- 테마를 선택하면 지도가 먼저 바뀌어야 한다.
- 검색 입력은 지도 갱신용 보조 도구로 둔다.

4. Place Detail
- 선택한 장소를 해석하는 상세 패널이다.
- 결과 카드의 복제본이 아니라, 방문 판단에 필요한 정보를 정리해야 한다.

## 4. 디자인 방향

- 전체 인상은 `관광 테마 큐레이션 서비스`에 가깝게 간다.
- command center, control room, dashboard 같은 인상은 제거한다.
- 데이터 서비스이긴 하지만, 화면은 차갑고 복잡한 분석도구처럼 보이면 안 된다.
- 사용자는 관광 맥락과 장소 분위기를 먼저 느끼고, 세부 정보는 나중에 읽어야 한다.

핵심 톤:
- 따뜻한 오프 화이트 배경
- 자연/도시를 함께 떠올리게 하는 그린-블루 계열 강조색
- 카드와 지도의 균형
- 복잡한 상태 패널 제거

## 5. 지도 디자인 원칙

- 지도는 항상 메인 시각 중심이다.
- 테마 탐색의 흐름이 잘 보이도록 마커와 선택 상태를 분명히 구분한다.
- 결과가 없더라도 지도 영역은 비어 보이지 않게 유지한다.
- 마커 클릭과 카드 클릭은 같은 선택 상태로 동기화한다.

마커 규칙:
- 기본 마커는 깔끔하고 작아야 한다.
- hover, selected 상태는 명확해야 한다.
- 과장된 HUD 스타일이나 군사용 표현은 쓰지 않는다.

## 6. 카드/패널 원칙

### 테마 카드
- 테마의 성격이 한눈에 보여야 한다.
- 이름, 한 줄 요약, 태그 정도만 노출한다.
- 테마 카드는 필터 묶음이 아니라 `탐색 시작점`이다.

### 결과 카드
- 장소 비교에 필요한 최소 정보만 보여준다.
- 대표 이미지가 있으면 적극 활용한다.
- 거리, 카테고리, 짧은 설명, 운영 메타 정도만 유지한다.

### 상세 패널
- 장소를 선택한 뒤 방문 판단을 돕는 정보 위주로 구성한다.
- 우선 정보:
  - overview
  - 운영 시간
  - 휴무 정보
  - 주차 여부
  - 반려동물 동반 여부
  - 위치
  - 추천 근거

## 7. 검색 UX 원칙

- 검색 입력은 항상 존재하지만 화면의 주인공은 아니다.
- 기본 상태는 테마 기반 결과가 먼저 보이는 것이 맞다.
- 사용자가 직접 문장을 넣어 현재 테마를 세밀하게 조정하는 흐름으로 설계한다.

## 8. 애니메이션 원칙

- 가벼운 hover, selection, fade 정도만 사용한다.
- 과한 launch overlay, dashboard reveal, event strip 모션은 제거한다.
- 지도와 카드의 반응이 부드럽게 이어지는 정도면 충분하다.

## 9. 하지 말아야 할 것

- command center, mission control 같은 표현을 다시 넣지 않는다.
- 불필요한 상태 배지, 로그 스트립, 운영 콘솔 UI를 만들지 않는다.
- 검색 결과를 개발자용 데이터 패널처럼 노출하지 않는다.
- 외부 API 명세를 프런트 용어로 직접 드러내지 않는다.

## 10. 기준 문구

- 메인 정의: `취향과 상황에 맞는 관광 테마를 고르면, 지도로 장소를 탐색하고 상세 정보를 해석할 수 있습니다.`
- 보조 설명: `서울은 스마트서울맵 맥락을 우선 사용하고, 전국은 TourAPI 기반 데이터로 자연스럽게 확장합니다.`
